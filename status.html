When each popup appears

Popup 1 — ARK Melts (product pages)
Opens only for engaged visitors:
  • Phone: after at least 5 seconds on the page and scrolling about a third down — someone actually reading the product.
  • Computer: same thresholds, then it waits for the mouse to head up to leave the page.
  • An alternative "Exit only" mode exists as a setting (never shows during reading), switchable without code.
  • The small teaser tab is never on the page at arrival. It appears only after someone closes the popup. Closing the teaser hides it for that visit. Clicking it always opens the popup.
Popup 2 — Leaving Already? (rest of the site)
Opens only on real leaving behavior — never on a timer:
  • Visitor has seen 3+ pages and spent 45+ seconds actually viewing the site (background tabs don't count),
  • and then makes a genuine exit move: mouse shooting to the top edge (desktop) or a long fast upward scroll (mobile). A casual small scroll-up doesn't trigger it.
  • Never on: the 4 Melts pages, cart, checkout, ad landing pages, policy pages.
Politeness rules (why nobody gets annoyed)
  • Maximum one popup per visit, across the whole store.
  • Close one popup → no other popup that visit (at most the small teaser on Melts pages).
  • Closed it? The Melts popup rests 7 days, the Leaving popup 30 days.
  • Signed up = never sees any popup or teaser again (shared across both popups).
  • Nothing ever interrupts cart or checkout.

Klaviyo connection (for the email team)

What happens when someone signs up
  • The popup adds the person to the Newsletter list — the same list as today. The existing PMA | Welcome Flow fires unchanged (Email #1 with WELCOME10, the extra-5% SMS series, everything).
  • The email and the phone number are submitted together at the end of the popup journey — so SMS consent exists before the flow starts. (Today's forms submit the email first, which can make the flow skip SMS #1.)
  • Typing an email is not consent — nothing is sent until the person clicks Continue and finishes. The success screen only appears after Klaviyo confirms receipt.
  • Every profile is tagged: custom_source ("ARK Popup - Product" / "ARK Popup - Exit") and a property popup_signup_source with the exact page. The email team can branch flow content on these anytime — no changes needed from the popup side.

Process

How changes are made
  • Everyday text/toggle changes: Saul edits them directly in the Shopify Theme Editor (ARK Popups section — switches, texts, trigger mode, cooldowns, page lists).
  • Design or behavior changes: requested through Saul → built by Claude → independently reviewed by Codex → tested on the hidden theme → only then released.
  • This page is part of the workflow: it is updated after every popup change, so it always shows the current truth.
